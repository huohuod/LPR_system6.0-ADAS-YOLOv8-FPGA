## 一、系统简介

本系统是一个**实时智能交通视觉分析平台**，以单目摄像头或视频流为输入，通过多模型融合推理，实现对道路交通场景的实时感知与分析：

- 检测并跟踪车辆、行人、红绿灯、斑马线
- 识别红绿灯状态（红 / 黄 / 绿）并稳定输出
- 检测车道线，提供车道保持辅助提示（LDWS / LKAS）
- 单目深度估计测距，实现**前车碰撞预警（FCW）**
- 检测**闯红灯**等交通违规行为
- 基于虚拟线的**车流量统计**
- 支持 **2×2 四宫格**分屏，四路画面独立识别

系统面向 FPGA 硬件加速与 AI 推理的竞赛场景，同时适配 GPU（CUDA）实时推理。

## 二、核心功能

| 功能 | 说明 |
|------|------|
| **车辆检测与跟踪** | YOLOv8 实时检测车辆/行人，IoU 多目标跟踪，绘制运动轨迹 |
| **红绿灯识别** | 专用 YOLO 模型定位 + HSV 颜色分类 + 时序投票稳定灯态 |
| **车道线检测** | UFLD 深度学习模型（上半象限）+ 传统 CV（下半象限），输出车道保持提示 |
| **碰撞预警（FCW）** | Depth Anything V2 单目测距，车距 < 2m 触发碰撞预警并记录 |
| **违规检测** | 车辆闯红灯、行人闯红灯检测，红框 + 文字标记 |
| **车流统计** | 虚拟检测线法，统计车辆穿越数量（上行/下行） |
| **四宫格视图** | 2×2 画面分割，每路独立识别，实时性能监控 |

## 三、技术架构

### 3.1 技术栈

| 组件 | 技术 | 说明 |
|------|------|------|
| 目标检测 | YOLOv8 (ultralytics) | 车辆 / 行人 / 红绿灯 / 斑马线 |
| 车道检测 | UFLD ONNX | 深度学习车道线，ResNet-18 主干 |
| 深度估计 | Depth Anything V2 | 单目相对深度，用于碰撞测距 |
| UI 框架 | PySide6 | macOS 深色风格界面 |
| 硬件加速 | CUDA 12.4 | GPU 实时推理 + fp16 |

### 3.2 数据流

```
摄像头/视频 → 采集线程 → UI 定时器(~30fps)
  → LPREngine.detect_full(frame)  [多步检测流水线]
    ├─ YOLO 车辆/行人/红绿灯/斑马线检测
    ├─ 红绿灯颜色稳定 (HSV + 时序投票)
    ├─ 轨迹跟踪 (IoU 多目标)
    ├─ 单目深度测距 (Depth Anything V2)
    ├─ 车道线检测 (UFLD / 传统CV)
    ├─ 碰撞预警 (车距 < 2m)
    ├─ 违规检测 (闯红灯状态机)
    └─ 结果绘制 + 碰撞记录
  → QImage → QPixmap → QLabel 显示
```

## 六、配置说明

系统配置集中在 `configs/` 目录下：

### 6.1 主配置 `configs/system.json`

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `model.device` | GPU 设备索引（"0" 或 "cpu"） | "0" |
| `model.conf_threshold` | 检测置信度阈值 | 0.4 |
| `model.iou_threshold` | NMS 重叠阈值 | 0.45 |
| `model.img_size` | YOLO 输入尺寸（320/416/480/640/800） | 640 |
| `model.fp16` | 半精度推理开关 | true |
| `pipeline.max_fps` | 目标帧率 | 30 |
| `pipeline.frame_queue_size` | 流水线队列大小 | 3 |
| `pipeline.enable_*` | 各检测模块开关（预处理/跟踪/红绿灯/行人/违规/多尺度） | true |
| `color.brightness/contrast/saturation` | 颜色校正（亮度/对比度/饱和度） | 0 |
| `color.wb_r/wb_g/wb_b` | 白平衡校正 | 0 |

### 6.2 深度估计配置 `configs/depth.json`

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `enabled` | 是否启用深度估计 | true |
| `input_size` | 深度模型输入尺寸 | 518 |
| `interval` | 降频：每 N 帧测一次距离 | 3 |
| `alpha` | 深度尺度因子（标定得到，`Z = alpha / rel`） | 标定值 |

> 深度尺度 `alpha` 通过「深度标定」功能标定：在画面中点击一个已知实际距离的地面点，输入距离（米），系统自动反算 `alpha` 并写回配置。

## 7. 使用指南

### 7.1 界面布局

侧边栏四个页面：

1. **监控** — 实时视频画面 + 性能仪表盘（FPS / 延迟 / CPU / 内存 / GPU / 显存）+ 运行日志
2. **统计** — FPS 历史、检测计数
3. **记录** — 碰撞预警记录（碰撞提醒 / 置信度 / 时间，最多 50 条）
4. **设置** — 模型参数 / 图像校正 / 系统设置

### 7.2 四宫格模式

- 点击监控页的「四路分割」开关进入 2×2 四宫格模式
- **Q1 / Q2**（上半）：完整检测（车辆、行人、红绿灯、车道线、违规）
- **Q3 / Q4**（下半）：车辆检测 + 碰撞预警（车距 < 2m）
- 四路画面独立识别，互不干扰

### 7.3 碰撞预警

- 单目深度估计实时测量前车距离
- 车距 **< 2m** 时触发碰撞预警：显示碰撞图标 + 记录到「记录」页
- 采用锁存机制，距离回升到 > 2m 才解除，避免闪烁

### 7.4 违规检测

- 红灯期间，车辆 / 行人闯红灯将被红色框标记，并显示「违规闯红灯」/「闯红灯」文字
- 违规框自动跟随目标移动

## 8. 测试方法

### 8.1 环境测试

验证 GPU / CUDA / ONNX 环境是否就绪：

```bash
python -c "import torch; print('CUDA:', torch.cuda.is_available(), torch.cuda.get_device_name(0))"
python -c "import onnxruntime; print('Providers:', onnxruntime.get_available_providers())"
```

- `torch.cuda.is_available()` 返回 `True`，且 `get_device_name` 显示 GPU 型号 → CUDA 就绪
- `onnxruntime` 的 Providers 包含 `CUDAExecutionProvider` → ONNX GPU 就绪

### 8.2 功能测试

1. **启动系统**：`python main.py --device 0`
2. **加载测试视频**：点击「文件」按钮，选择测试视频文件（如路况视频）
3. **车辆/红绿灯检测**：观察画面中车辆框、红绿灯框及颜色标注
4. **车道线检测**：观察道路车道线拟合与「车道保持」提示
5. **碰撞预警**：让车辆接近前车至 2m 内，观察碰撞图标触发 + 「记录」页新增记录
6. **违规检测**：红灯期间有车辆/行人通过路口，观察红色违规框 + 文字标记
7. **四宫格模式**：开启「四路分割」，观察 2×2 画面各自独立识别

### 8.3 性能测试

- 监控页仪表盘实时显示 FPS、检测延迟、CPU/内存/GPU/显存占用
- 单路模式下 GPU 满载时，FPS 应达到实时水平
- 四宫格模式下因 4 路并行推理，FPS 约为单路的 1/4

## 十、技术亮点

1. **多模型融合** — YOLOv8 + UFLD + Depth Anything V2 协同工作
2. **GPU 硬件加速** — CUDA + fp16 半精度推理，实时处理
3. **四宫格并行识别** — 2×2 画面独立检测，适配多路视频
4. **单目深度测距** — 无需双目/激光雷达，单摄像头实现碰撞预警
5. **时序稳定机制** — 红绿灯投票稳定、车道线 EMA 平滑、碰撞锁存，抗闪烁
6. **全中文深色 UI** — macOS 风格界面，性能监控仪表盘
